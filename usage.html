1 · 这是什么

Linux in HTML 在浏览器标签页里真跑一台 Debian GNU/Linux 12 (bookworm) i386 虚拟机。v86 把 x86 CPU 用 WebAssembly JIT 模拟出来，客户机是一块完整的 384 MB ext4 磁盘镜像（不是内存 rootfs），所以有真的内核、真的 sysvinit 用户态、真的 dpkg / apt，也有真的 TCP 网络。终端里敲的每条命令都在客户机里真的执行，不是前端演出来的，也不是录屏或 UI 复原。

页面本体是静态文件，配套一个很小的 Node 服务器 server.js：把静态资源和磁盘分块（支持 HTTP Range，按需读取）发给浏览器，同时提供 WISP 中继，让客户机连得上互联网。

2 · 快速开始

需要先装好 Node.js（能跑 node 与 npm 即可）。在项目目录里执行：

cd linux-in-html
npm install      # 首次运行装依赖，整个项目只有 ws 一个依赖
node server.js   # 默认 http://127.0.0.1:8080/

然后用浏览器打开 http://127.0.0.1:8080/。页面会自动开机、自动登录 root，等它进桌面就能用。

  • 懒得敲命令：Windows 双击 start.bat，macOS / Linux 执行 ./start.sh。两个脚本检测到没有 node_modules 时会自动 npm install，再直接跑 server.js。
  • 不要用 file:// 直接打开 index.html：浏览器不允许本地文件读取 wasm 引擎和磁盘镜像，页面会提示你改用 node server.js。
  • 端口被占用：node server.js --port 8081，再访问 http://127.0.0.1:8081/。
  • 想让局域网里的手机或同事访问：node server.js --host 0.0.0.0（或加 --allow-any-host），然后用宿主机 IP:8080 打开。默认只监听 127.0.0.1，别人连不上是正常的。
  • 整套文件也可以放到 GitHub Pages 这类静态托管上，但那样没有本地 Node 进程，网络要另外给一个公网中继，见「网络」一节。

3 · 登录与自动开机

  • 账号是 root / root。串口控制台和画面里的 tty1 都能用这组账号登录。
  • 通常不需要手动登录：页面启动后会自动在串口控制台以 root 登录，顺手配好 guest 网络，然后进桌面。桌面里打开的终端窗口直接就是 root shell。
  • 首次打开会先出现三步初始设置（主机名、时区、主题），改动会写进客户机与浏览器本地；不想改就点「跳过」，之后在「设置」里还能改，也能在设置里重新调出向导。
  • 想自己登一次也行：打开「虚拟机屏幕」应用看 tty1 的 VGA 画面，在 login: 后面输入 root，密码 root（密码不回显）。
  • 开机时间：单核模拟、没有 KVM，从启动到进桌面大约 25–40 秒；首次启动要按需读取磁盘分块，会更接近上限；手机上更慢。
  • 刷新页面等于重新引导客户机；磁盘上的改动不会丢（见「磁盘持久化」）。

4 · 桌面与顶栏

进系统后是一套自绘桌面：桌面壁纸、顶部顶栏、Dock，窗口由页面自己管理，不依赖客户机里的 X11。

  • 顶栏：左边「活动」（应用总览），中间是当前窗口名与时钟，右边依次是内核版本、主题切换（亮 / 暗，选择存在浏览器本地，下次打开保持）、网络、扬声器、电源。
  • Dock：每个图标对应一个应用，点一下打开或切回对应的窗口。
  • 窗口：拖动标题栏移动，按钮做最小化 / 最大化 / 关闭；窗口可以缩放，终端和文件列表会按新尺寸重排。
  • 多窗口：Alt+Tab 在窗口之间切换；有两个工作区，用 Ctrl+Alt+← / → 切换。
  • 桌面右键：桌面空白处右键弹出菜单，提供常用的桌面入口。
  • 手机 / 窄屏：Dock 变成底部一行横排，窗口按屏幕尺寸适配，触控目标放大到手指好点的尺寸。

5 · 应用一览

终端

  • 直连客户机 ttyS0，等于坐在那台 Debian 前面。常用命令：ls cat grep ps top df -h free -m dpkg -l。
  • 方向键上下翻命令历史、左右移动光标，Tab 补全，Ctrl 组合键都是客户机 bash 的标准行为。
  • 复制粘贴：选中文本后 Ctrl+Shift+C 复制，Ctrl+Shift+V 或系统粘贴粘贴。
  • 改变窗口大小后，已有输出会按新的列数重排。
  • 手机上会唤起软键盘：点终端输入区就能打字，回车发送命令。
  • 串口带宽有限，刷屏特别快的命令（dmesg、yes）会显得很慢，这是通道限制，不是卡死。

文件

  • 列出客户机里的真实目录（等价于 ls -la），左侧是根目录快捷入口，可以进出目录。
  • 点文本文件会用 cat 预览；权限、大小、修改时间都在列表里。

文本编辑器

  • 打开客户机里的文件、编辑后写回。写入采用 base64 分块追加，写完会回读字节数并比对 sha256 校验，对不上会提示。

相机与图库

  • 打开相机窗口会自动用浏览器 getUserMedia 申请摄像头权限并直接出预览，不需要再点按钮；浏览器询问时选「允许」。
  • 如果之前拒绝过，窗口里会显示失败原因和「重新授权」按钮，点它可以再次发起申请。
  • 拍照结果进图库，可删除、可保存 / 下载到本机；关闭窗口会释放摄像头。

计算器

  • 随手算个数用的小计算器，不必为了算一步退回终端。

设置

  • 分外观、声音、高级、性能、系统信息、网络几个分区；性能与系统信息读的是客户机实时数据，网络分区管理 WISP 中继与 guest 网络（见下一节）。

虚拟机屏幕

  • 显示客户机 tty1 的 VGA 画面。串口或桌面出问题时，可以在这里手动登录、看内核输出。

已上传文件

  • 列出通过「文件」注入客户机的文件，带大小、sha256 与时间，可重新注入或清理记录（明细见「上传与安装 .deb」一节）。

关于与许可 · 帮助

  • 「关于与许可」给出版本与组件许可证信息，「帮助」是快速上手入口；两处都能打开本页。

6 · 网络（WISP 中继）

浏览器本身不能开 TCP 连接，所以客户机里的 socket 是通过 WISP 中继转发出去的，链路是：

guest（enp0s10）  ──virtio-net──▶  v86（浏览器 / WebAssembly）
                                       │
                                       │  WISP over WebSocket
                                       ▼
                                   server.js（本机 Node）
                                       │  TCP
                                       ▼
                                     互联网

对客户机里的 curl、apt 来说，这就是普通互联网：网卡是普通 virtio 网卡，v86 把它接成一条 WebSocket，用 WISP 把 TCP 流多路复用出去，server.js 在宿主机上真的 net.connect 到目标，再把数据原路送回。

server.js 一个进程干三件事：静态文件、磁盘分块的 HTTP Range 读取、/wisp/ 中继。它默认只监听 127.0.0.1。

本机模式（默认就能用）

用 node server.js 起服务时，页面会自动在串口控制台登录 root 并配好 guest 网络：网卡地址 192.168.86.100/24，网关和 DNS 都是 192.168.86.1（这是 v86 内置 NAT 的约定地址）。在「设置 → 网络」里能看到当前状态和重连按钮。

在终端里验证：

ip -4 addr show dev enp0s10
curl -sS http://example.com -o /dev/null -w '%{http_code}\n'
# 期望输出 200
apt-get update

镜像里的 apt 源默认已经换成阿里云（/etc/apt/sources.list.d/debian.sources），所以 apt-get update 可以直接跑通。想换源就改这个文件里的域名，例如改成 mirrors.tuna.tsinghua.edu.cn。

https 需要先装证书包。镜像里没有 CA 证书，curl https://… 会报证书相关的错误；先执行 apt-get install -y ca-certificates 再试。纯 http 和 apt 不受影响。
DNS 走本机中转。客户机的 53 端口由 v86 交给浏览器，页面再把这条 DoH 请求转给 server.js 的 /dns-query，由它用 UDP 去问真实 DNS（默认 223.5.5.5，随后 114.114.114.114，可用 --dns 改）。这样解析不依赖浏览器能否访问公网 DoH；Pages 上没有这个路由，页面会自动回落到公网 cloudflare-dns.com。
手动配置 guest 网络的等价命令（正常情况下用不到） 
IF=$(ls /sys/class/net | grep -v '^lo' | head -n1)
ip link set $IF up
ip addr add 192.168.86.100/24 dev $IF
ip route replace default via 192.168.86.1 dev $IF
printf 'nameserver 192.168.86.1\n' > /etc/resolv.conf

GitHub Pages 等静态托管

Pages 上只有静态文件，没有 Node 进程，虚拟机照样能开机，但客户机没有外网。这时需要给它一个公网可达的 WISP 地址：

  • 在页面「设置 → 网络」里填 wss://你的中继域名/wisp/，点「重连」；
  • 或者用 URL 参数直接打开：index.html?wisp=wss://你的中继域名/wisp/。
  • 中继可以自己部署：任何能跑 Node + WebSocket 的机器上跑本项目的 server.js，前面套一层 Nginx 反代并开 TLS，就是公网的 wss://…/wisp/。
Pages 是 https 页面，浏览器不允许它连 ws://，所以公网中继必须是 wss://。

局域网访问

手机想连电脑上跑的虚拟机：node server.js --host 0.0.0.0，用电脑的局域网 IP:8080 打开页面即可；中继是同源的 /wisp/，不用另外配。想屏蔽某些目标主机可以加 --block host1,host2。

7 · 磁盘持久化

  • 客户机是一块完整的 384 MB ext4 磁盘镜像，不是内存 rootfs。你在 guest 里装的包、改的文件、写的脚本都真在这块盘上。
  • 磁盘写入的块存在浏览器的 IndexedDB 里：刷新页面、关掉浏览器再打开，改动还在，可以接着用。
  • 每个浏览器一份，互不相通。换浏览器、换设备、开无痕窗口，看到的都是另一份磁盘（或出厂状态）。
  • 想回到干净状态：设置里提供「清除磁盘改动」，清掉之后下次启动就是出厂镜像。
  • 上传的文件、桌面上 .deb 安装出来的图标也存在浏览器本地（IndexedDB / localStorage），换浏览器同样看不到。
  • 清除浏览器站点数据会把上面这些都清掉（磁盘改动、设置、上传记录）。想长期保留，就别清站点数据。

8 · 上传与安装 .deb

  • 「文件」面板可以把本机文件通过串口分块注入客户机。串口是慢通道，几十 KB 级别的文件比较合适，别拿它传几十 MB 的东西。
  • 上传 .deb 会走客户机里真实的 dpkg -i 安装，然后解析包里的 .desktop，在桌面生成图标，点图标就在客户机里启动对应程序。
  • 装好的包留在客户机磁盘里，图标记录存在浏览器本地，刷新或重开浏览器后还在。
  • 只是想在 guest 里放个小脚本、小配置文件时，上传通常比在终端里手打快。

10 · 性能参考

  • 单核模拟、没有 KVM 硬件加速，性能大致相当于 2000 年代初的机器。进桌面 25–40 秒，apt install 要有耐心。
  • 首次启动要按需读取磁盘分块（384 MB 分成多块拉取），比之后慢；之后有浏览器缓存会好一些。
  • 手机 CPU 弱、内存小，会更慢，也更容易在 apt 这类重活上卡住。
  • 图形桌面不是这台机器的主场：可以在 guest 里自己 apt install xorg，跑得动但不会快。
  • 串口是终端通道，带宽有限；dmesg、yes 这类刷屏命令看着卡是正常的。

11 · 已知限制

  • 没有 GPU 加速、没有声卡直通。
  • guest 网卡在 v86 里叫 enp0s10；网上教程里的 eth0 / ens33 配置别直接照抄。
  • 镜像不带 CA 证书，https 需要先 apt-get install -y ca-certificates。
  • 通过串口单次注入的文件不要太大，几十 KB 级别最稳。
  • 只有一块 384 MB 磁盘，装大包之前先 df -h 看看空间。
  • 中继和磁盘分块都要经过浏览器与本机 / 服务器，网络差时首次加载和 apt 都会慢。
  • 每个浏览器的磁盘互相独立，A 浏览器里装的东西不会在 B 浏览器里出现。

12 · 常见问题

双击 index.html 打不开，提示要用 server.js

不要用 file:// 打开。按「快速开始」跑 npm install 与 node server.js，再访问 http://127.0.0.1:8080/。

一直停在引导画面

首次启动要读磁盘分块，25–40 秒是正常范围，手机更久。先看引导日志是否还在滚动；如果一两分钟完全没动静，刷新页面或重启页面里的虚拟机；仍然不行就看终端 / 串口输出的最后一行报错。

客户机没有网，curl 不是 200

先在「设置 → 网络」看 guest 网络状态，点重连或重新配置；本机模式确认 server.js 还在跑。Pages 模式确认填的是公网 wss://…/wisp/，并且那个中继服务真的在。

如果报的是 Could not resolve host 而不是连接超时，问题在 DNS：确认 server.js 还在跑（它同时负责 /dns-query），再确认本机能解析域名；Pages 模式下没有这个路由，会回落到公网 DoH，浏览器访问不到 cloudflare-dns.com 时就只能靠 IP 直连。

apt-get update 失败

先确认网络验证通过（上面那个 curl 返回 200）。apt 源默认指向阿里云，国内一般没问题；换源就改 /etc/apt/sources.list.d/debian.sources。磁盘满了会报空间不足，用 df -h 看一眼。

curl https:// 报证书错误

镜像没带 CA 证书，先 apt-get install -y ca-certificates。

相机打不开 / 黑屏

浏览器弹权限询问时选允许；之前点过拒绝，就在相机窗口里点「重新授权」。部分浏览器要求页面在前台，或者要求 https 页面才给摄像头权限。

刷新以后装的东西还在吗

在。磁盘改动存在 IndexedDB 里，刷新只是重新引导；清除站点数据或者换浏览器才会丢。

终端敲字没反应

先点一下终端窗口拿到焦点；手机上点输入区唤起软键盘。确认页面已经进桌面，而不是还在引导。

8080 端口被占用

用 node server.js --port 8081，然后访问 http://127.0.0.1:8081/。

13 · 项目结构与技术栈

全部是原生 HTML / CSS / JS，没有前端框架，也没有外部 CDN、外部字体、外链图片：页面本体完全离线可用。

index.html                桌面入口（窗口系统挂在它上面）
assets/css/desktop.css    桌面、顶栏、Dock、窗口样式
assets/js/term.js         终端渲染器（ttyS0）
assets/js/wm.js           窗口管理器、桌面、顶栏、工作区
assets/js/apps.js         终端 / 文件 / 编辑器 / 相机 / 图库 / 计算器 / 设置等应用
assets/js/extras.js       附加应用与工具（虚拟机屏幕、关于、帮助等）
assets/js/boot.js         引导流程、串口自动登录、guest 网络配置
assets/js/anim.js         界面动效
assets/js/bridge.js       与 v86 / WISP / IndexedDB 之间的桥接
server.js                 静态服务 + Range 分块读取 + WISP 中继
lib/                      v86 引擎、SeaBIOS / SeaVGABIOS
images/                   内核 vmlinuz、initrd、384 MB 磁盘分块
licenses/                 第三方许可证全文（GPL-3.0 等）

关键实现：

  • 模拟器 v86：x86 → WebAssembly JIT，画面渲染在 canvas；磁盘按 HTTP Range 分块按需拉取。
  • 网络：WISP over WebSocket，由 server.js 转成真实 TCP。
  • 持久化：客户机磁盘的增量写在浏览器 IndexedDB。
  • 终端：直连串口 ttyS0，渲染与键盘事件都在宿主侧处理。
